## Что это за проект

Торговый робот для Московской биржи на T-Invest API (Т-Банк). Одновременно это **учебный
проект**: владелец — студент, он учится профессиональной архитектуре (SOLID, DI, паттерны).
Файлы с кодом — его учебники.

Студент: 1С-программист, знает JavaScript (MERN). Объяснения строятся на аналогиях из
1С; словарь соответствий — раздел 20 архитектуры.

## Окружение

- Сервер Ubuntu 24.04, пользователь `trader` без sudo. Проект — `~/trader-agent`.
- Node.js 24 через nvm (`.nvmrc`). Процессы в будущем запускаются под PM2.
- T-Invest API требует сертификатов Минцифры: `NODE_EXTRA_CA_CERTS=$HOME/certs/russian-trusted-ca.pem`
  (уже прописано в npm-скриптах).
- Пока работаем **только с песочницей**: `sandbox-invest-public-api.tbank.ru`.

## Секреты — абсолютные правила

- **Никогда** не открывать, не выводить и не цитировать `.env`, токены и ключи — даже частично.
  Проверить наличие переменной можно только маской: `sed -E 's/=(.{6}).*/=\1…/' .env`.
- Токены в код, тесты, логи, коммиты и сообщения об ошибках не попадают. В `.env.example`
  хранятся только имена переменных.
- Если в выводе команды случайно оказался секрет — сразу сказать об этом студенту.

## Правила кода

- **TypeScript strict.** Запуск через `tsx`, проверка — `npm run typecheck`, тесты — `vitest`.
- **Структура** — строго по разделу 4 архитектуры. Файлы в `kebab-case`, один класс или
  интерфейс на файл. Модули общаются только через свой `index.ts`.
- **Правило зависимостей:** домен ничего не импортирует; `new` для инфраструктурных классов —
  только в `src/app/composition-root.ts`.
- **Деньги** — только `Money` (bigint, нано). **Время** — только через `Clock`, никакого
  `new Date()` в ядре.
- **Ошибки** — наследники `AppError`; наружу сообщаем через `ErrorReporter`.
- **Шапка** в каждом файле с кодом — по шаблону из раздела 12 архитектуры (ФАЙЛ, СЛОЙ, РОЛЬ,
  ПАТТЕРН, ИСПОЛЬЗУЕТСЯ, ТЕСТЫ, 1С).
- **Комментарии** объясняют *почему*, а не *что*. Над каждым паттерном и неочевидным
  решением — поясняющий блок: это учебный проект.
- **Тесты** лежат рядом с кодом: `money.ts` → `money.test.ts`.

## Порядок работы

1. Перед правками прочитать нужный раздел архитектуры и текущий спринт.
2. После правок: `npm run typecheck` и `npm test`. Результат показать студенту.
3. **Коммиты делает студент сам.** Claude предлагает текст сообщения в формате
   Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`).
4. Архитектурное решение, которого нет в документах, — сначала обсудить со студентом и
   оформить ADR, потом писать код.
5. В конце спринта — документ `docs/sprints/sprint-NN-<тема>.md` и тег `sprint-NN`.

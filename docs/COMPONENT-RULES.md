# Предметные правила

- Текущий scope — документация и подготовка разработки; первая продуктовая задача
  определяется после T002. Не обещать готовый анализ рынка по наличию каркаса.
- Не запускать scripts/smoke.mjs как локальную проверку: он делает сетевые запросы
  и при отсутствии песочницы создаёт счёт и пополняет его виртуальными средствами.
- Доступы старого сервера неизвестны. Не читать .env, токены, ключи и секреты других
  компонентов; не показывать даже первые символы секретов. Проверять только наличие
  файла/имени параметра без чтения значения, когда это нужно разрешённой задаче.
- Не использовать ключи/среду/пользователей регистратора FCIA для продукта.
- Аналитический вывод должен отличать наблюдение, вычисление и гипотезу; фиксировать
  источник и момент данных. Успешный тест кода не доказывает выгодность стратегии.
- Имя trader-agent сохраняется. Переименование, автоматическая торговля и расширение
  продуктовой области требуют решения; эти документы их не выполняют.
- Не называть .aps обязательной: управление сейчас в docs/ и работает без APS.

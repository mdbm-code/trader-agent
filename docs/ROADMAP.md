## Sprint 02 — Каркас, DI и ошибки

**Результат**
- `tsconfig.json`, скрипты `typecheck`, `test`, `dev`; зависимости `tsx`, `vitest`, `zod`.
- `src/shared`: `Money` и `Quantity` (с тестами), `Clock`, `Logger`, `EventBus`, конфиг.
- **Система ошибок**: иерархия `AppError`, `ErrorReporter` (Композит), приёмник в консоль,
  ограничитель повторов, маскировка секретов, `installProcessGuards`.
- Порты и доменные типы всех модулей; заглушки `identity`, `tenancy`, `signals`, `billing`,
  каналов уведомлений.
- `composition-root.ts`, `main-worker.ts`; smoke-тест на новой архитектуре.
- ADR 001–010.

**Готово, когда:** `typecheck` и `test` зелёные; искусственно брошенное исключение в
`main-worker` попадает в консоль в едином формате, токен в тексте ошибки замаскирован.

## Sprint 03 — Коннектор T-Invest и рыночные данные

**Результат**
- Контракт коннектора: `ConnectorManifest`, `Connector`, `AccountGateway`, `ConnectorRegistry`.
- Контрактные тесты для любого коннектора; T-Invest их проходит (в песочнице).
- Клиент T-Invest с декораторами: повторы, ограничение частоты запросов, логирование.
- Справочник инструментов, история свечей в MongoDB, `npm run fetch-history`.
- `TelegramAlertSink`: критичные ошибки приходят вам в Telegram.

**Готово, когда:** история загружается и докачивается; падение API приходит в Telegram ровно
один раз, а не 500.

## Sprint 04 — Стратегии, бэктест, визуализация

**Результат**
- `TradingStrategy`, `StrategyDefinition`, `StrategyRegistry`; ваша стратегия и эталонная
  `sma-crossover`.
- `BacktestEngine` с `SimulatedGateway` и `FakeClock`, модель комиссий и проскальзывания.
- **HTML-отчёт**: свечной график с отметками входов и выходов, кривая капитала, просадки,
  таблица сделок (TradingView Lightweight Charts). Открывается в браузере.

**Готово, когда:** `npm run backtest -- --bot <конфиг>` выдаёт воспроизводимый отчёт с графиками.

## Sprint 05 — Риск-менеджмент

**Результат:** `RiskEngine`; правила `KillSwitch`, `TradingHours`, `MaxPosition`, `DailyLoss`;
`PositionSizer`; риск-профиль бота; проверка совместимости бота с манифестом площадки.

## Sprint 06 — Торговля в песочнице

**Результат:** `TradingOrchestrator`; `BotScheduler` по расписанию из `TradingSchedules`;
машина состояний бота; `Reconciler`; изоляция ошибок по ботам (Bulkhead); PM2 под `trader`.

**Готово, когда:** неделя торговли в песочнице без вмешательства; перезапуск не создаёт
дублей заявок.

## Sprint 07 — Команды владельца (Telegram и Max)

**Результат:** уведомления о сделках; команды `/status`, `/positions`, `/pause`, `/resume`,
`/kill` принимаются только от вашего аккаунта; `MaxChannel` — второй канал, реализующий тот же
порт.

## Sprint 08 — Эксплуатация

**Результат:** JSON-логи с ротацией, health-check, метрики, алерт «робот молчит», бэкап
MongoDB, регламент обновлений.

## Sprint 09 — Боевой запуск

**Результат:** full-access токен только на отдельный счёт, малый капитал, сравнение с песочницей,
регламент инцидентов. **Готово, когда:** месяц без инцидентов.

## Sprint 10 — ИИ-лаборатория

**Результат**
- `src/interfaces/mcp/` — наш MCP-сервер с инструментами `list_strategies`, `get_candles`,
  `run_backtest`, `get_backtest_report`. Только чтение и только бэктест.
- Процесс `main-agents.ts`; `LlmClient`; агент-исследователь: гипотеза → код или параметры
  стратегии → бэктест → отчёт → **ваше утверждение**.
- Дневной бюджет расходов на API для каждого агента.

**Что изучаем:** как LLM пользуется инструментами, почему инструменты агента должны быть
безопасными, человек в контуре.

## Sprint 11 — Новостной агент

**Результат:** `InsightSource`; чтение выбранных источников; `Insight` по строгой схеме;
хранилище point-in-time; `StrategyContext.insights`; стратегия с новостным фильтром проверяется
**вперёд** в песочнице.

**Что изучаем:** prompt injection и защита от неё, структурированный вывод, почему бэктест
LLM-сигналов на прошлом завышает результат.

## 🚦 Юридический чекпойнт (до Sprint 12)

Ниже — ориентиры, окончательный ответ даст юрист.

| Модель | Суть | На что обратить внимание |
|---|---|---|
| Продажа ПО | Пользователь сам запускает робота со своим токеном | Наименее регулируемый вариант: лицензия на ПО и оферта |
| **Платные сигналы** (Sprint 15) | Сервис сообщает подписчикам, что покупать | Индивидуальные инвестиционные рекомендации в РФ вправе давать только инвестиционные советники из реестра Банка России |
| Торговля на чужих счетах | Робот торгует деньгами клиентов по их токенам | Близко к доверительному управлению и автоследованию — это лицензируемая деятельность |
| Криптоплощадки | Коннекторы к криптобиржам и DEX | С 01.09.2026 криптовалюты для резидентов РФ — только через лицензированных посредников |

Для всех моделей: хранение чужих токенов — это персональные данные (152-ФЗ) и ответственность
за утечку; правила брокера об использовании API третьими лицами; SMS-рассылки — отдельные
требования к рассылкам.

## Sprint 12 — Пользователи и API

**Результат:** `identity`: регистрация, вход, сессии; JWT (access ~15 мин, refresh в
`httpOnly`-cookie с ротацией); роли `owner`/`viewer`/`admin`; REST API и SSE для живых
обновлений.

## Sprint 13 — Мультиарендность и секреты

**Результат:** `TenantContext` во всех сценариях; фильтр по `tenantId` в каждом репозитории;
`EncryptedMongoSecretVault`; лимиты API на каждый токен; журнал аудита.

## Sprint 14 — Веб-кабинет

**Результат:** `web/` на React + Redux Toolkit / RTK Query с `baseQueryWithReauth`;
мониторинг ботов и позиций в реальном времени; админка; настройки стратегий по инструментам
(формы строятся по `paramsSchema`); отчёты бэктестов с графиками.

## Sprint 15 — Сигналы подписчикам

**Результат:** режим бота `signal`; `SignalDistributor`; Outbox + `DeliveryWorker`
(`main-delivery.ts`); каналы Telegram, Max, SMS; точки связи подписчика; лимиты и повторы
по каналам.

## Sprint 16 — Биллинг

**Результат:** тарифы, оплата через платёжного провайдера, доступ к ботам по подписке, лимиты
по тарифу.

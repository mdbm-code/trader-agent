## Sprint 02 — Каркас и DI

**Цель.** Проект переходит на TypeScript и получает полную структуру каталогов. Общее ядро
реализовано, у всех модулей есть интерфейсы и заглушки, Composition Root собирает приложение,
тесты проходят.

**Результат**
- `tsconfig.json`, скрипты `typecheck`, `test`, `dev`; зависимости `tsx`, `vitest`, `zod`.
- `src/shared`: `Money` (с тестами), `Clock` + `SystemClock` + `FakeClock`, `Logger`,
  `EventBus`, `NotImplementedError`, загрузка и валидация конфига.
- `src/modules/*`: порты и доменные типы всех модулей; заглушки для `identity`, `tenancy`,
  `billing`, `notifications`.
- `src/app/composition-root.ts` и `main-worker.ts`, который собирает приложение и пишет в лог
  «готов».
- Smoke-тест переписан на новую архитектуру: `src/interfaces/cli/smoke.ts`.
- ADR 001–006 в `docs/architecture/adr/`.

**Что изучаем:** все пять принципов SOLID на живом коде, DI через конструктор, Composition Root,
объекты-значения, модульные тесты с фейками.

**Готово, когда:** `npm run typecheck` и `npm test` зелёные, `npm run smoke` работает через
новые классы, в коде ядра нет ни одного `new` для инфраструктурных классов.

## Sprint 03 — Рыночные данные

**Результат**
- `TInvestRestClient` с декораторами: повторы, ограничение частоты запросов, логирование.
- `InstrumentCatalog`: поиск инструментов, кеш справочника (лоты, шаг цены, режим торгов).
- Загрузка истории свечей в MongoDB (time-series коллекция), команда `npm run fetch-history`.
- `CsvMarketDataProvider` для офлайн-бэктестов.

**Что изучаем:** адаптер и антикоррупционный слой, декораторы, репозиторий, лимиты API.

**Готово, когда:** история по выбранным инструментам загружена, повторный запуск докачивает
только недостающее.

## Sprint 04 — Стратегии и бэктест

**Результат**
- `TradingStrategy`, `StrategyDefinition`, `StrategyRegistry`.
- Первая **ваша** стратегия и эталонная `sma-crossover` для сравнения.
- `BacktestEngine` с `SimulatedGateway` и `FakeClock`; модель комиссий и проскальзывания.
- Отчёт: доходность, максимальная просадка, доля прибыльных сделок, кривая капитала.

**Что изучаем:** паттерн «Стратегия», реестр и фабрика, почему внедрённое время делает бэктест
возможным, ловушки бэктестов (заглядывание в будущее, переподгонка).

**Готово, когда:** `npm run backtest -- --bot <конфиг>` выдаёт воспроизводимый отчёт.

## Sprint 05 — Риск-менеджмент

**Результат**
- `RiskEngine` и правила: `KillSwitch`, `TradingHours` (календарь MOEX, выходные сессии),
  `MaxPosition`, `DailyLoss`.
- `PositionSizer`: фиксированная сумма, процент от капитала или по волатильности.
- Риск-профиль в настройках бота.

**Что изучаем:** цепочка ответственности, спецификации, тестирование граничных случаев.

**Готово, когда:** каждое правило покрыто тестами, бэктест учитывает риск-профиль.

## Sprint 06 — Торговля в песочнице

**Результат**
- `TradingOrchestrator`, `BotScheduler` (расписание по свечам и торговым сессиям).
- Потоковые данные (stream) вместо опроса — где это оправдано.
- `Bot` с машиной состояний: `stopped → starting → running → paused → error`.
- `Reconciler`: сверка с брокером при старте.
- Запуск под PM2 от имени `trader`, автозапуск после перезагрузки.

**Что изучаем:** оркестратор, машина состояний, шина событий, идемпотентность, отказоустойчивость.

**Готово, когда:** робот неделю без вмешательства торгует в песочнице и переживает перезапуск
без двойных заявок.

## Sprint 07 — Уведомления и Telegram (для владельца)

**Результат**
- `NotificationService` подписан на события.
- `TelegramChannel`: сделки, отказы риск-менеджера, ошибки.
- Команды: `/status`, `/positions`, `/pause`, `/resume`, `/kill`. Команды принимаются только
  от вашего chat id.

**Что изучаем:** паттерн «Команда», адаптер внешнего API, безопасность входящих команд.

## Sprint 08 — Эксплуатация

**Результат:** структурные логи (JSON) с ротацией, health-check, метрики (задержки API, ошибки,
PnL), алерт «робот не отвечает», бэкап MongoDB, регламент обновления.

**Что изучаем:** наблюдаемость, сквозная функциональность без засорения бизнес-кода.

## Sprint 09 — Боевой запуск

**Результат:** full-access токен только на отдельный счёт робота, малый капитал, сравнение
результатов бумажной и реальной торговли, регламент инцидентов («что делать, если…»).

**Готово, когда:** месяц реальной торговли без инцидентов, результаты сопоставимы с бэктестом
и песочницей.

## 🚦 Юридический чекпойнт (до Sprint 10)

Модели монетизации по-разному регулируются, и архитектура продукта зависит от выбранной модели.
Ниже — ориентиры, окончательный ответ даст юрист.

| Модель | Суть | На что обратить внимание |
|---|---|---|
| Продажа ПО | Пользователь сам запускает робота со своим токеном и сам принимает решения | Наименее регулируемый вариант. Нужна лицензия на ПО и оферта |
| Сигналы и рекомендации | Сервис говорит, что купить | Индивидуальные инвестиционные рекомендации в РФ вправе давать только инвестиционные советники из реестра Банка России |
| Торговля на чужих счетах | Робот торгует деньгами клиентов по их токенам | Близко к доверительному управлению и автоследованию — это лицензируемая деятельность |

Независимо от модели:
- **Хранение чужих токенов** — это ответственность за утечку и работа с персональными данными
  (152-ФЗ).
- **Условия брокера.** Нужно проверить, что правила Т-Банка допускают выбранную схему
  использования API и токенов третьих лиц.

## Sprint 10 — Пользователи и API кабинета

**Результат:** модуль `identity` (регистрация, вход, сессии/JWT, сброс пароля), роли
`owner`/`viewer`, REST API для ботов, счетов и настроек. Модуль `interfaces/http`.

**Что изучаем:** аутентификация и авторизация, конвейер middleware, DTO и валидация на границе.

## Sprint 11 — Мультиарендность и секреты

**Результат:** `TenantContext` во всех сценариях, фильтрация по `tenantId` во всех
репозиториях, `EncryptedMongoSecretVault` (envelope encryption), учёт лимитов API по каждому
токену, аудит действий.

**Что изучаем:** изоляция данных, шифрование, модель угроз.

## Sprint 12 — Веб-кабинет и Telegram для всех

**Результат:** React-кабинет в `web/`: счета, боты, настройки стратегий по инструментам (формы
строятся по `paramsSchema`), журнал сделок. Привязка Telegram к кабинету: одноразовый код →
chat id, дальше двусторонний обмен в рамках своего кабинета.

## Sprint 13 — Биллинг

**Результат:** тарифы, подписки, ограничения по тарифу (число ботов, стратегий, инструментов),
интеграция с платёжным провайдером.

**Что изучаем:** политики доступа, feature flags.

# ADR 001 — TypeScript вместо JavaScript

## Контекст

Проект строится вокруг SOLID и DI (раздел 5–6 архитектуры): модули общаются через порты
(интерфейсы), зависимости внедряются явно. В обычном JavaScript интерфейсов нет — соответствие
класса порту никто не проверяет, кроме тестов и внимательности разработчика.

## Решение

Пишем на TypeScript в strict-режиме. Код выполняется напрямую через `tsx` (без отдельного шага
сборки), проверка типов — отдельной командой `tsc --noEmit`, не блокирующей запуск.

## Альтернативы

- **JavaScript + JSDoc-типы.** Даёт частичную проверку типов, но интерфейсы и дженерики в JSDoc
  громоздки, а строгость проверки слабее.
- **TypeScript с шагом сборки (`tsc` эмитит `.js`, потом `node dist/...`).** Ближе к тому, как
  часто разворачивают TS в проде, но лишний шаг усложняет цикл разработки без выгоды на этом
  этапе проекта.

## Последствия

- Каждый файл с кодом — либо интерфейс (порт), либо его реализация; SOLID и DI становятся
  проверяемыми компилятором, а не только соглашением.
- `npm run typecheck` — отдельная команда обратной связи, независимая от исполнения кода;
  запускается локально и в CI ровно так же.
- `tsconfig.json` использует `NodeNext` + `allowImportingTsExtensions`, чтобы относительные
  импорты писались с честным `.ts`, а не с `.js`, указывающим на несуществующий скомпилированный
  файл.

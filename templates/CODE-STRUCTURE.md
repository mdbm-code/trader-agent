## Примеры выбора, не универсальные предписания

| Вид проекта | Возможное разделение, которое нужно адаптировать |
|---|---|
| C#/.NET-служба | Host/lifecycle, сценарии, предметные правила при наличии, инфраструктура и адаптеры ОС; UI/MVVM не требуются службе |
| C# desktop | UI/ViewModel, сценарии, модели/правила, адаптеры; MVVM при поддержке выбранного UI-стека |
| Kotlin/Android | Features и UI/state, данные/репозитории, платформенные порты; domain/use cases по сложности, не обязательный класс на каждое действие |
| Python-служба или CLI | Пакеты по возможностям, чистая логика, адаптеры ввода-вывода и entrypoint; маленькому скрипту достаточно нескольких функций |
| TypeScript web/API | Features, UI либо routes/controllers, сценарии/валидация, API/storage adapters; учесть границу клиента и сервера |
| 1С 7.7/8 | Обработки/формы, прикладная логика, правила отображения данных и адаптеры обмена в рамках возможностей платформы; снимок конфигурации и генерируемое отделить от авторского кода |

Это иллюстрации архитектурного выбора, а не новые обязательные библиотеки,
названия каталогов, требования разнести всё на репозитории или лицензия переписать проект.
